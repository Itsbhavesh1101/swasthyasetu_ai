# P11 Document AI / OCR readiness-gate review

**Review date:** 2026-10-20

**Baseline:** `main @ 7aad4dce8c68d008e98287d769d83d109c3cb46b`

**Decision scope:** Readiness for P11-A/B/C/D/E; documentation is not implementation or deployment approval

## 1. Decision

P11 live patient/clinician document processing is **BLOCKED**. No gate has recorded approval for a real population or clinical environment. Current evidence supports only separately prompted engineering work using synthetic, nonmedical fixtures, no network egress, no live file access, and no runtime activation.

The nine gates derive from repository evidence: **0 APPROVED, 5 OPEN, 4 BLOCKED**. `OPEN` means a design/approval is missing but an isolated technical subset may be proposed; `BLOCKED` means a downstream live workflow has unmet prerequisite authority and must not start. Neither status authorizes code in this documentation work unit.

- `backend/app/modules/documents/` contains only `.gitkeep`; no document domain/service/route exists.
- Conceptual `clinical_documents`, `document_processing_runs`, and `document_extractions` are absent from Alembic; head is `p7a_0007`.

- PostgreSQL `OutboxRepository` exists and is transaction-scoped; no document event integration exists and exactly-once is not claimed.
- `/documents` is an unavailable patient-web placeholder. No clinician source viewer exists.
- P8-C and P9-C live gates remain blocked, and P10 records 0/9 live clinician gates approved.

## 6. Required decisions and evidence to close gates

At minimum, accountable humans must record:

1. allowed environments/populations/uploader roles, lawful purpose, consent/sharing, ownership/transfer, and clinician assignment;
2. exact supported formats and tested byte/page/pixel/runtime quotas, scanner/quarantine/sandbox design, and hostile-file acceptance evidence;
3. storage provider/configuration, encryption/key custody, region, isolation, retention/deletion/legal hold/backup, preview and incident handling;
4. reviewed schema/migration, lifecycle constraints, idempotency, transaction/outbox, durable worker, revocation/cancellation and cleanup design;
5. reproducible OCR benchmark results, selected pinned artifacts, language/handwriting/table thresholds, license/processor terms, resource budget and rollback;
6. registry/contract review and strict source/provenance/verification versioning;
7. independent clinical validation for each medical field, human reviewer authority, correction/promotion workflow, and explicit abstention criteria;
8. source-view authorization, patient/clinician copy, privacy and accessibility evidence;
9. threat model, privacy/security/clinical/model-governance reviews, pilot monitoring/incident/rollback, and explicit production enablement.

Until each applicable decision is recorded, no live document or OCR capability may be inferred from this pack.
